# Stage 2 实现说明

## 1. 范围

本阶段只实现：Authentication Hook、ConnID/UserID/SessionID、Session Manager、New Login Wins、Heartbeat、Idle Timeout、在线状态 Metrics。

明确不实现 Backend 路由、可靠消息、断线恢复、Redis、多节点、限流和完整 Graceful Drain。

## 2. 鉴权

`internal/auth.Authenticator` 是 Gateway 与身份系统之间的 Hook：

```go
type Authenticator interface {
    Authenticate(context.Context, string) (string, error)
}
```

Gateway 本身不解释生产 Token。默认 `DevAuthenticator` 只用于本地开发，接受 `user:<UserID>`。生产环境应通过 `gateway.WithAuthenticator(...)` 注入真实实现。

控制协议：

- MessageType 10：AuthRequest；Payload 为 protobuf-wire `AuthRequest{token}`；
- MessageType 11：AuthResult；Payload 包含 ok/user_id/session_id/error_code；
- MessageType 12：HeartbeatRequest；
- MessageType 13：HeartbeatResponse。

## 3. Session

`internal/session.Manager` 使用单一读写锁维护：

```text
UserID -> Session
ConnID -> Session
```

Session 在 Stage 2 中只有 ACTIVE 与终止语义；尚未启用 Stage 5 的 DISCONNECTED_GRACE。

重复登录冻结策略为 **New Login Wins**：同一 UserID 新注册时，Manager 在同一临界区内替换旧映射并返回被替换 Session，Server 再在锁外关闭旧 Conn。旧 Conn 的 close callback 使用 ConnID 删除 Session，因此不会误删新 Session。

## 4. 未认证消息

业务消息定义为 `MessageType >= 1000`。未认证 Connection 发送业务消息会被拒绝，不进入业务处理路径。

Stage 1 的 EchoRequest 是诊断控制消息，不属于业务 MessageType，因此保留为未认证可用，方便连接层回归测试。

## 5. Heartbeat / Idle Timeout

每个 Connection 保存原子 `LastSeen`。成功解析且通过 Envelope 校验的消息都会刷新活跃时间。

Server 只有一个 heartbeat scanner goroutine：

```text
HeartbeatCheckInterval = 15s (default)
IdleTimeout            = 45s (default)
```

扫描时只处理 OPEN Connection；超过 IdleTimeout 则以 `heartbeat_timeout` 原因幂等 Close。HeartbeatRequest 只有已认证连接会收到 HeartbeatResponse。

这种设计避免每连接再增加一个 heartbeat goroutine，也使半开连接回收逻辑集中、容易做 race 测试。

## 6. Metrics

Stage 2 新增：

- `game_gateway_sessions{gateway_id,state="active"}`；
- `game_gateway_auth_total{gateway_id,result}`；
- `game_gateway_heartbeat_timeouts_total{gateway_id}`。

继续禁止 UserID、SessionID、ConnID、RequestID、RoomID 作为 Prometheus label。
