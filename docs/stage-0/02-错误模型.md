# 阶段 0：错误模型

## 1. 目标

错误必须能回答三个问题：

1.  错误发生在哪一层；
2.  对当前消息、Connection、Session 的影响是什么；
3.  调用方是否允许重试。

## 3. 错误影响级别

-   **Message-level**：只拒绝当前消息，不关闭连接。
-   **Connection-level**：关闭当前 Conn；Session 是否保留由 Session
    状态机决定。
-   **Session-level**：终止或替换 Session。
-   **Process-level**：仅用于真正无法继续运行的初始化/基础设施错误；客户端输入不得触发进程
    panic。

## 4. 稳定错误码原则

对外错误码是协议契约，文本 message 不是契约。

建议概念结构：

``` text
Error {
  code: stable machine-readable code
  message: human-readable diagnostic text
  retryable: bool
  request_id: optional correlation id
}
```

阶段 0 只冻结分类和语义；具体 Protobuf enum 数值在阶段 1
落地协议文件时确定。

## 5. Backend 错误映射原则

Backend 业务错误可以穿过 Gateway 返回，但必须经过内部契约映射：

-   Gateway 不解释业务规则；
-   Gateway 可以识别 timeout、unavailable、routing、overload
    等基础设施错误；
-   未识别 Backend 错误统一映射为受控错误，不能导致 panic；
-   Backend 故障不得导致 Gateway 无限等待或无限堆积消息。
