# 阶段 0：系统边界与术语

## 1. 三方边界

### Client

Client 是 Gateway 的外部连接方。

Client 负责：

-   建立、维护和关闭与 Gateway 的长连接；
-   按约定 Envelope 编解码消息；
-   提供鉴权材料；
-   发送心跳/活跃信号；
-   保存后续断线恢复所需的客户端状态；
-   对需要可靠语义的消息参与 Seq / ACK 流程。

Client 不得：

-   直接依赖某个 BackendInstance 的地址；
-   决定 Room 实际落在哪个 BackendInstance；
-   假设 Gateway 内存在游戏世界、Tick、AOI、移动、碰撞或技能逻辑。

### Gateway

Gateway 是客户端接入层，也是本项目唯一实现主体。

Gateway 负责：

-   Connection 生命周期；
-   Session 生命周期；
-   鉴权接入；
-   协议编解码与校验；
-   心跳、Idle Timeout 与僵尸连接回收；
-   MessageType 路由；
-   User -\> Room 与 Room -\> BackendInstance 路由；
-   有界发送队列、背压与限流；
-   可靠消息基础机制；
-   断线恢复；
-   必要的多节点共享状态；
-   Metrics、日志、Trace；
-   优雅下线。

Gateway 明确不负责：

-   游戏世界状态；
-   Tick Loop；
-   AOI；
-   玩家移动计算；
-   碰撞；
-   技能/战斗结算；
-   匹配算法本身；
-   聊天业务本身。

**边界规则：Gateway 可以识别消息的传输语义和路由元数据，但不能解释
Payload 中的游戏规则。**

### Backend

Backend 是 Gateway 的内部下游服务统称，例如 Match、Chat、Room、State
Sync。

Backend 负责：

-   实现自身业务语义；
-   接收 Gateway 已完成连接/会话层处理后的内部请求；
-   返回业务结果或明确错误；
-   在约定时间内响应，或由 Gateway 按 timeout / 快速失败策略处理。

Backend 不负责客户端 socket 生命周期，也不能要求 Client 直接连接某个
BackendInstance。

## 2. 核心术语

  ------------------------------------------------------------------------------------------
  术语                    定义                                身份/生命周期
  ----------------------- ----------------------------------- ------------------------------
  Conn                    一次客户端到单个 Gateway            由唯一 ConnID
                          的物理/逻辑长连接实例               标识；断线即结束，不恢复原
                                                              Conn

  ConnID                  Gateway 为每次连接分配的唯一标识    每次新建连接都必须变化

  User                    通过鉴权后识别出的玩家主体          由 UserID 标识；生命周期独立于
                                                              Conn

  UserID                  Backend/Gateway 共同认可的用户标识  鉴权成功后确定

  Session                 一个已认证玩家在 Gateway            由 SessionID
                          中的会话上下文                      标识；未来允许跨短暂断线恢复

  SessionID               Session 唯一标识                    新 Session 生成；Resume
                                                              成功时保持

  Room                    Backend                             由 RoomID 标识；Gateway
                          侧的逻辑房间/游戏实例路由单元       只保存路由，不解释游戏状态

  RoomID                  Room 的逻辑标识                     用于 User -\> Room 路由

  BackendInstance         某类 Backend 的一个可寻址服务实例   由 BackendInstanceID 标识

  GatewayID               一个 Gateway 进程/实例的唯一标识    阶段 6 使用，多节点路由需要

  MessageType             Envelope                            Gateway
                          中用于决定消息类别/路由的稳定标识   可据此路由，但不解释业务
                                                              Payload

  RequestID               一次请求-响应关联 ID                用于关联请求、响应和日志

  MessageID               可靠消息的唯一 ID                   用于 Retry/Dedup；阶段 4 实现

  Seq                     某方向可靠消息的单调序号            用于顺序、ACK、恢复；阶段 4
                                                              实现

  Ack                     对已接收可靠序号的确认信息          阶段 4 实现

  ResumeToken             恢复 Session 的短期凭证             阶段 5 实现，不得无限复用
  ------------------------------------------------------------------------------------------

## 3. 身份关系

``` text
User (UserID)
  └── Session (SessionID)
        └── current Conn (ConnID)

User -> Room (RoomID)
Room -> BackendInstance (BackendInstanceID)
Conn -> Gateway (GatewayID)
```

约束：

1.  一个 Conn 在任意时刻最多绑定一个 Session。
2.  一个有效 Session 在稳定态最多拥有一个 current Conn。
3.  同一 User 是否允许多个 Session
    由"重复登录策略"决定；本项目默认策略见 Session 状态机。
4.  Conn 断开不等价于 User 消失；阶段 5 引入 Grace Period 后，Session
    可暂时脱离 Conn。
5.  Gateway 不以 Payload 内业务字段决定
    BackendInstance，路由必须经过显式路由契约。
