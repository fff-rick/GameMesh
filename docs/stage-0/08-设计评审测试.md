# 阶段 0：设计评审测试

本文件按阶段任务要求，以设计模拟方式逐项验证登录、断网、重复登录、Backend
故障和 Gateway Shutdown。阶段 0 不执行网络代码测试。

## Case 01 --- 正常登录

前置：Conn 已 OPEN，尚未认证。

事件：Client 提供有效鉴权材料。

期望唯一结果：

1.  鉴权得到 UserID；
2.  创建 SessionID；
3.  Session 从 UNAUTHENTICATED -\> ACTIVE；
4.  current Conn 指向当前 ConnID；
5.  之后业务消息才允许进入路由流程。

**评审：PASS。**

## Case 02 --- 鉴权失败

事件：Token 非法/过期。

唯一结果：

-   不创建 ACTIVE Session；
-   业务消息不允许通过；
-   Session/临时认证上下文进入 TERMINATED；
-   错误分类为 AUTH。

**评审：PASS。**

## Case 03 --- ACTIVE 时突然断网

阶段 2-4 唯一结果：

-   Conn：OPEN -\> CLOSING -\> CLOSED；
-   Session：ACTIVE -\> TERMINATED。

阶段 5+ 唯一结果：

-   Conn：OPEN -\> CLOSING -\> CLOSED；
-   Session：ACTIVE -\> DISCONNECTED_GRACE；
-   Grace Period 内合法 Resume 可回到 ACTIVE；
-   超时则 TERMINATED。

**评审：PASS。阶段差异已显式定义，不存在同阶段双重结果。**

## Case 04 --- 同账号重复登录

默认策略：New Login Wins。

唯一结果：

-   并发竞争必须决出一个新登录胜者；
-   旧 Conn 进入 CLOSING；
-   旧 Session TERMINATED；
-   新登录建立新的 ACTIVE Session；
-   稳定态不存在两个同策略下的 ACTIVE Session。

**评审：PASS。**

## Case 05 --- Backend Timeout / Unavailable

唯一结果：

-   当前业务请求映射为 BACKEND_TIMEOUT 或 BACKEND_UNAVAILABLE；
-   Gateway 不无限等待、不无限排队；
-   ACTIVE Session 身份状态不因单次 Backend 故障改变；
-   Conn 默认保持 OPEN，除非另有连接层错误。

**评审：PASS。**

## Case 06 --- Gateway Shutdown

唯一结果：

-   停止接受新连接；
-   不创建新 Session；
-   新业务请求停止接收或明确失败；
-   已有 Conn 进入关闭/Drain 路径，最终 CLOSED；
-   单节点、无迁移能力时 Session 最终 TERMINATED；
-   Shutdown 不能留下无限 goroutine/queue。

**评审：PASS。**

## Case 07 --- 超大消息

事件：客户端发送完整 Envelope wire size \> 64 KiB。

唯一结果：

-   分类 MESSAGE_TOO_LARGE；
-   不解析/执行 Payload 业务；
-   当前 Conn 关闭；
-   进程不得 panic。

**评审：PASS。**

## Case 08 --- 未知 MessageType

唯一结果：

-   分类 PROTOCOL；
-   不路由到任意 Backend 猜测处理；
-   默认 message-level 拒绝；若持续恶意违规可升级 connection-level
    关闭。

**评审：PASS。**

## 评审结论

本阶段要求的五个核心模拟场景均得到唯一明确结果；额外覆盖超大包和未知
MessageType。实现阶段必须以这些状态机和错误语义作为测试
oracle，若需要修改，应先更新阶段 0 契约并记录原因。
