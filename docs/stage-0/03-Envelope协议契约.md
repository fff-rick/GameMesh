# 阶段 0：Envelope 协议契约

## 1. Envelope 概念字段

依据方案设计，统一 Envelope 至少包含：

  -----------------------------------------------------------------------------------------------------------------
  字段                    必需性                  语义
  ----------------------- ----------------------- -----------------------------------------------------------------
  Version                 必需                    协议主版本，用于兼容性判断

  MessageType             必需                    消息类型/路由标识

  RequestID               条件必需                请求-响应关联；非请求消息可为空

  MessageID               可靠消息必需            可靠消息唯一标识，用于去重

  Seq                     可靠消息必需            发送方向序号

  Ack                     条件必需                对可靠消息接收进度的确认

  Payload                 可选                    业务或控制消息内容；Gateway 不解释游戏业务规则

  Timestamp               必需                    发送端生成消息时的时间戳，主要用于诊断/观测，不作为唯一顺序依据
  -----------------------------------------------------------------------------------------------------------------

## 2. 版本规则

-   第一版协议主版本定义为 `1`。
-   Gateway 必须显式检查 Version。
-   不支持的主版本：返回/记录 `PROTOCOL_VERSION_UNSUPPORTED`，不继续解释
    Payload。
-   新增可选字段不得改变旧字段语义。
-   删除字段、改变字段语义或 wire type 视为破坏性变更，需要新主版本。
-   未知字段允许底层 Protobuf 按兼容规则忽略；未知 MessageType
    不允许静默执行业务。

## 3. MessageType 分层

MessageType 分为：

-   **CONTROL**：连接/鉴权/心跳/ACK/恢复等 Gateway 控制消息；
-   **BUSINESS_RELIABLE**：聊天、关键指令等未来需要 Seq/ACK/Retry/Dedup
    的消息；
-   **BUSINESS_UNRELIABLE**：允许丢弃的高频状态/位置类消息；
-   **BUSINESS_COALESCIBLE**：允许"新状态覆盖旧状态"的状态类消息。

具体业务 MessageType 数值由后续 Gateway \<-\> Backend
契约定义，但必须先声明其可靠性语义。

## 4. 可靠性语义

  ---------------------------------------------------------------------------------------------------------
  类型                      允许丢弃        允许合并  需要 ACK/Retry 典型用途
  ------------------ --------------- --------------- --------------- --------------------------------------
  CONTROL_CRITICAL                否              否      视控制协议 鉴权结果、恢复结果、关闭原因

  RELIABLE                        否              否              是 聊天、关键指令、重要事件

  UNRELIABLE                      是              否              否 高频瞬时状态

  COALESCIBLE                     是              是              否 位置/朝向/状态快照等"最新值优先"消息
  ---------------------------------------------------------------------------------------------------------

因此，**未来允许不可靠的消息已经明确为高频瞬时状态类消息，以及明确声明为
COALESCIBLE
的最新状态类消息**。可靠性必须由消息契约声明，不能由队列满时临时猜测。

## 5. 消息大小上限

阶段 0 冻结以下默认值：

-   **客户端 -\> Gateway 单个完整 Envelope 最大 wire size：64 KiB**
-   **Gateway -\> 客户端单个完整 Envelope 最大 wire size：64 KiB**
-   **Gateway 内部 RPC 单条消息建议上限：256 KiB**
-   超过客户端边界 64 KiB：分类为 `MESSAGE_TOO_LARGE`，拒绝并关闭当前
    Conn。
-   大对象、地图资源、录像、文件等不应通过实时 Gateway Envelope
    传输，应使用独立对象/资源通道。

说明：64 KiB
是第一版安全边界，不是性能结论。后续若压测和真实协议证明需要调整，必须作为协议变更记录，不允许无上限放开。

## 6. 顺序与时间

-   `Timestamp` 不用于解决网络乱序。
-   可靠消息顺序以 `Seq` 为准。
-   `MessageID` 用于身份和 Dedup，不替代 Seq。
-   `RequestID` 用于请求关联，不要求全局排序。

## 7. Payload 边界

Gateway 可以：

-   校验 Envelope；
-   根据 MessageType 选择 Backend；
-   执行可靠性、限流、背压策略。

Gateway 不可以：

-   读取"技能伤害""移动速度""碰撞体"等业务字段后做游戏判定；
-   修改业务规则含义；
-   将游戏状态变成 Gateway 的权威状态。
