阶段 0 不声称已经达到某个连接数目标。这里建立**可复现记录格式**；阶段 1
首次实现长连接后输出第一份真实基线。

## 3. 压测场景

### S0 --- Idle Connections

目标：测连接本身的资源成本。

变量：

-   连接数逐级提升；
-   建连速率固定；
-   建连后仅维持必要心跳。

记录：CPU、RSS、goroutine、单连接平均内存、建连失败率。

### S1 --- Steady Bidirectional Messaging

目标：建立稳定消息吞吐和延迟基线。

变量：

-   固定连接数；
-   每连接固定消息频率；
-   固定 Payload 大小档位：64 B / 256 B / 1 KiB / 4 KiB。

记录：msg/s、P50/P95/P99、CPU、RSS、GC、错误率。

### S2 --- Connection Churn

目标：观察频繁建连/断连资源回收。

变量：每秒新建/关闭固定比例连接。

记录：建连率、断连率、RSS 是否回落、goroutine 是否回落、失败率。

### S3 --- Slow Client / Send Queue

目标：验证慢客户端不会制造无限内存增长。

阶段 1 实现有界队列后执行。记录 Queue Depth、Drop/Disconnect、RSS
和其他正常连接延迟。

### S4 --- Burst

目标：验证短时突发消息。

先稳定运行，再在短窗口提升消息速率。记录
P99、队列深度、错误率、恢复到稳态所需时间。

## 5. 基线比较规则

-   同一场景比较必须记录机器规格和 Git Commit。
-   不以"10 万连接"作为预设成功标准。
-   每个阶段优先与上一阶段同配置结果比较。
-   性能优化不得以破坏正确性、队列上限或错误处理为代价。
-   结果异常时保留原始数据，不只保留"最好的一次"。
