# Stage 5：测试报告

## 1. 覆盖范围

本阶段在既有单元和集成测试上，增加三个端到端故障验收用例：

| 测试 | 注入条件 | 可观察结果 |
|---|---|---|
| `TestResumeSucceedsWhenBackendIsUnavailable` | 已认证连接断开后停止已配置的独立 gRPC Backend | Resume 成功；恢复后的业务请求返回可重试 `backend_unavailable` |
| `TestConcurrentResumeTokenUseHasOneWinner` | 两个新 WebSocket Connection 并发提交同一 Token | 恰好一个 `ResumeResult.ok=true`；另一个为 `resume_token_invalid` |
| `TestGraceExpiryReleasesReliablePending` | 产生可靠出站 Pending 后断开，等待 Grace 到期 | `ReliablePendingCount()` 从 1 归零 |

这些测试使用真实 Gateway、WebSocket、Session、Router 和 Reliability Manager。第一项使用独立启动后再停止的真实 gRPC Backend；测试断言协议输出，而不是 mock 调用次数。

全量 race detector：


结果：PASS。全部 package 通过，输出中没有 race report；Gateway 用时 5.033s。

## 4. 相关既有恢复覆盖

除本任务新增用例外，Gateway 回归还覆盖：

- Grace 内恢复保持 SessionID；
- 过期 Token 拒绝；
- 成功 Resume 后旧 Token 重放拒绝；
- 旧连接关闭不移除已恢复 Session；
- 已认证连接不能再次 Resume；
- Grace 期间 Pending 保留；
- Resume 后 Pending 按原 Seq 和原字段重放；
- Grace 期间 retry scanner 不消耗 retry；
- Server Close 与认证/恢复生命周期并发安全。

## 5. 结论与限制

本阶段的故障验收、普通全量回归与 race 回归均通过。首次新增测试运行直接通过是一个 TDD RED 证据缺口：它反映实现已先由前置任务落地，而不是未验证的测试；该事实已保留在本报告中。测试结论仅覆盖单 Gateway 进程内恢复，不推断多节点或重启后的行为。
