# Stage 5：断线恢复验收报告

## 1. 验收范围

Stage 5 在**单个 Gateway 进程的内存范围内**完成短暂断线恢复：已认证客户端可在 Grace Period 内恢复原 Session 和可靠消息状态，而无需重新认证或重新建立后端游戏上下文。

本阶段不提供 Redis 持久化、跨 Gateway 路由、跨进程 Resume Token 共享或故障转移。多节点恢复是后续阶段的工作；在当前范围内，单节点内存模型比提前引入外部状态组件更简单且可验证。

## 3. 关键验收结论

### 会话与令牌

- Resume Token 由 CSPRNG 生成，为不透明的 128-bit 随机值；它不写日志，也不作为 Metrics label。
- 成功恢复只绑定原有 Session，SessionID 不变；服务端在同一原子恢复操作中轮换 Token，因此旧 Token 立即无效。
- 同一 Session 只有一个有效 Connection。并发恢复时只有取得旧 Token 的一个请求能完成绑定，其他请求得到 `resume_token_invalid`。

### Backend 与业务语义

恢复路径不调用 Router 或 Backend。即使已配置的 gRPC Backend 已停止，`ResumeResult.ok=true` 仍会返回；恢复后的下一条业务消息才遵循既有路由和 Backend 错误映射，并返回可重试的 `backend_unavailable`。

### 可靠性与回收

Grace 期间保持 Seq、ACK、Dedup Window 和 Pending。恢复成功后先发送 `ResumeResult`，再按 Seq 升序重放尚未 ACK 的原始 Envelope，保留 MessageID、Seq、MessageType、RequestID 与 Payload。Grace 到期时 Session 与 Reliability 状态一并删除，Pending 总数归零。
