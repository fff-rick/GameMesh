# Stage 3：Backend 路由实现说明

## 1. 本阶段范围

本阶段只实现 Gateway -> Backend 的基础路由链路，不进入 Stage 4 的 Seq / ACK / Retry / Dedup。

实现内容：

- `MessageType -> BackendType` 静态路由；
- `User -> Room` 静态路由；
- `Room -> BackendInstance` 静态路由；
- BackendClient 抽象与 Registry；
- Backend RPC timeout；
- Backend 错误映射；
- 不重试、快速失败；
- Backend RPC 计数与耗时 Metrics；
- gRPC `.proto` 内部契约；
- Fake Backend 集成测试。

## 2. 核心结构

```text
Authenticated Client
       |
       v
Game Gateway
       |
       +-- MessageType -> BackendType
       +-- UserID -> RoomID
       +-- RoomID -> BackendInstance
       |
       v
BackendClient.Handle(ctx, BackendRequest)
```

Gateway 只读取 Envelope 的基础路由元数据，不解释 Payload 中的游戏规则。Payload 原样复制给 Backend。

## 3. 内部 Backend 契约

`api/proto/backend.proto` 定义：

```text
service BackendService {
  rpc Handle(BackendRequest) returns (BackendResponse);
}
```

`BackendRequest` 包含：

- UserID；
- SessionID；
- RoomID；
- MessageType；
- RequestID；
- Payload；
- Timestamp。

`BackendResponse` 包含：

- MessageType；
- Payload；
- ErrorCode。

`internal/backend/wire.go` 提供与该 `.proto` 字段编号一致的 Protobuf wire 编解码，并有 round-trip 测试。

## 4. 路由模型

`internal/routing.StaticRouter` 使用 RWMutex 保护以下表：

```text
messageBackend: MessageType -> BackendType
userRoom:       UserID -> RoomID
roomInstance:   RoomID -> BackendInstance
```

Resolve 必须完整走完三层映射；未知 MessageType、User 无 Room、Room 无 Instance、BackendType 不匹配均返回不同错误，不猜测路由。

## 5. Backend 调用

`internal/backend.Caller`：

- 每次调用创建带 deadline 的 Context；
- timeout 默认由 `Config.BackendRPCTimeout` 控制；
- 不自动 Retry；
- transport unavailable 映射为 `ErrUnavailable`；
- deadline 映射为 `ErrTimeout`；
- Backend 声明的业务错误映射为 `BackendError`。

Backend 故障不会改变 Session ACTIVE 状态。

## 6. Client 错误映射

Stage 3 新增控制消息 `MessageTypeError = 14`，Payload 为：

```text
ErrorResponse {
  error_code
  retryable
}
```

主要错误：

- `routing_unknown_message_type`；
- `routing_user_room_not_found`；
- `routing_backend_unavailable`；
- `backend_timeout`；
- `backend_unavailable`；
- `backend_internal`；
- Backend 业务错误码原样作为受控业务错误返回。

## 7. Metrics

新增：

```text
game_gateway_backend_rpc_total{backend_type,method,result}
game_gateway_backend_rpc_seconds_count{backend_type,method}
game_gateway_backend_rpc_seconds_sum{backend_type,method}
```

不使用 UserID / SessionID / RoomID / RequestID 等高基数 label。

## 8. 当前环境限制

执行环境无法访问 `proxy.golang.org`，本地也没有缓存 `google.golang.org/grpc`。因此本阶段无法编译、启动和验证真实 `grpc-go` ClientConn/Server transport。

为避免伪实现：

- 没有使用 `net/rpc` 或 HTTP 冒充 gRPC；
- 已冻结真实 gRPC `.proto` 服务契约；
- Gateway 内部通过 `BackendClient` 隔离 transport；
- Fake Backend 使用同一 BackendClient/Request/Response 契约完成所有路由、timeout、错误、并发测试。

当 grpc-go 可获取时，只需增加实现 `BackendClient` 的 gRPC transport adapter，不需要修改客户端 Envelope 或 Gateway 路由核心。
