## 3. 慢客户端测试方法

使用一个会阻塞 `WriteBinary` 的 deterministic fake transport，模拟客户端停止读取服务端数据：

1. write loop 被第一条写阻塞；
2. 后续消息进入容量为 2 的 Send Queue；
3. Queue 达到容量后继续 `Enqueue`；
4. 必须返回 `ErrSendQueueFull`；
5. 断言 `len(queue) <= cap(queue)`。

这样不依赖本机 TCP buffer 大小和调度时序，可稳定验证“无无限队列”。

## 4. Race Detector 发现与修复

第一次执行 `go test -race ./...` 时发现：Server Shutdown 可能在 Connection 已加入 registry、但 `Start()` 尚未完成 `WaitGroup.Add(2)` 时执行 `Wait()`，造成 WaitGroup Add/Wait race。

修复：goroutine 计数在 `newConnection` 构造阶段固定，发生在 Connection 对 Server registry 可见之前；`Start()` 只负责状态切换与启动 goroutine。

修复后再次执行：

```text
go test -race ./...
```

所有 package PASS，无已知 race。

## 5. 资源回收

客户端关闭和服务端关闭测试都会等待 `Server.ConnectionCount()` 回到 0。Connection `Close()` 幂等，socket 被关闭，read/write loop 退出，registry 条目移除。
