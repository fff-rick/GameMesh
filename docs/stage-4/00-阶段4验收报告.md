## 4. 阶段验收逐项检查

### 重复消息不会重复产生业务效果

PASS。

可靠入站 MessageID / Seq 在 Backend 路由前登记。完全重复的包只返回累计 ACK，不再次调用 Backend。集成测试对 Backend 调用次数做严格 `== 1` 断言。

### ACK 丢失可触发预期重发

PASS。

客户端故意不发送 ACK 后，Gateway 在 RetryInterval 后重发同一个 Envelope；MessageID / Seq / Payload 保持不变。延迟 ACK 到达后 Pending 清除。

### Pending Queue 有严格上限

PASS。

`ReliablePendingLimit` 是硬上限。达到上限后不会继续增长；由于可靠消息不可静默丢弃，当前 Connection 按 `reliable_pending_full` 明确关闭。

### 不存在无限重试

PASS。

每条 Pending 受 `ReliableMaxRetries` 限制。次数耗尽后 Pending 删除并关闭当前连接，自动化测试验证该路径。

### 所有可靠性语义均有明确文档

PASS。

`docs/stage-4/01-可靠消息语义.md` 明确定义：分类、MessageID、Seq、累计 ACK、Dedup、Retry、Pending Limit、并发 ACK、Seq 边界和 Stage 4 断线行为。
