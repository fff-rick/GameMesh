## 3. Gateway 集成测试

覆盖：

### 重复可靠请求

同一个 `MessageID=m1, Seq=1` 连续发送两次：

- 第一次收到 ACK 并进入 Backend；
- 第二次只收到 ACK；
- Backend 调用计数最终严格等于 1。

结果：PASS。

### 乱序

首条可靠消息直接发送 Seq=2：

- Gateway 返回 `reliable_out_of_order`；
- `retryable=true`；
- Backend 调用计数为 0。

结果：PASS。

### 丢 ACK / 延迟 ACK

Gateway 发送可靠响应后，测试客户端故意不 ACK：

- RetryInterval 后收到相同 MessageID / Seq / Payload；
- 延迟发送 ACK 后 Pending 归零；
- 后续 scanner 不再继续产生 Pending Retry。

结果：PASS。

### ACK 前断线

可靠响应已进入 Pending，但客户端在 ACK 前主动关闭：

- Connection 回收；
- Session 回收；
- 对应可靠 Pending 归零。

结果：PASS。

### 最大重试

设置 `ReliableMaxRetries=1`：

- 首次发送；
- 一次重发；
- 再次超时后不继续无限重发；
- Pending 清理；
- Connection 关闭。

结果：PASS。

### Pending Overflow

设置 `ReliablePendingLimit=1`，客户端不 ACK 第一条可靠响应，再产生第二条可靠响应：

- Pending 不超过 1；
- Connection 以可靠队列溢出策略关闭。

结果：PASS。

## 4. 最终验证命令

普通全量回归：

```text
gofmt -l .
go test ./... -count=1
go vet ./...
go build ./...
```

结果：PASS。

全量 race detector：

```text
go test -race ./... -count=1
```

最终完整返回：PASS。

首次运行 race 时，由于冷缓存编译在当前容器超过 5 分钟未完成，因此没有将那次超时误记为 PASS；拆包预热后重新执行完整命令，所有 package 正常返回。

可靠性压力回归：

```text
go test ./internal/reliability ./internal/gateway \
  -run 'TestReliable|TestAckConcurrentWithCollectDue' \
  -count=20
```

结果：PASS。

## 5. 结论

Stage 4 要求的可靠消息故障场景均具有自动化测试，且普通测试、race detector、vet、build 与 20 轮可靠性压力回归均通过。
