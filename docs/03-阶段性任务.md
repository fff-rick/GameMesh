# Game Gateway：阶段性任务

> 原则：每个阶段都必须形成"目标 -\> 实现范围 -\> 测试 -\>
> 验收"的闭环。上一阶段没有验收，不进入下一阶段。

## 阶段 0：项目契约与性能基线定义

### 阶段目标

在写业务实现前固定边界、协议术语和测试指标，防止后续 Gateway 与 State
Sync 合并时接口反复修改。

### 任务

-   定义 Client/Gateway/Backend 三方边界；
-   定义 Conn、Session、User、Room、BackendInstance 等术语；
-   定义错误分类；
-   定义 Envelope 字段；
-   定义消息大小上限；
-   定义连接状态机；
-   定义 Session 状态机；
-   定义核心 Metrics；
-   定义压测场景与机器规格记录模板。

### 阶段测试

进行设计评审测试：逐项模拟登录、断网、重复登录、Backend 故障、Gateway
Shutdown，确认每种情况下状态机有唯一明确结果。

### 阶段验收

-   所有状态转换均有文档；
-   Gateway 与游戏逻辑边界没有模糊项；
-   已明确哪些消息未来允许不可靠；
-   已建立性能测试记录模板。

------------------------------------------------------------------------

## 阶段 1：单节点长连接 Gateway

### 阶段目标

建立最小可工作的 Client \<-\> Gateway
通道，只解决连接、收包、发包和关闭。

### 任务

-   WebSocket 接入；
-   Connection 生命周期；
-   统一 Envelope；
-   包大小限制；
-   有界 Send Queue；
-   基础结构化日志；
-   Connection Metrics。

### 阶段测试

-   单客户端连续收发；
-   多客户端并发连接；
-   非法包；
-   超大包；
-   客户端主动关闭；
-   服务端主动关闭；
-   慢客户端导致 Send Queue 堆积。

### 阶段验收

-   无无限队列；
-   连接关闭后资源能够回收；
-   非法客户端不能导致进程 panic；
-   race detector 无已知竞态；
-   输出第一份并发连接与消息吞吐基线。

------------------------------------------------------------------------

## 阶段 2：鉴权、Session 与心跳

### 阶段目标

从"连接"升级为"已认证玩家会话"。

### 任务

-   Authentication Hook；
-   ConnID/UserID/SessionID；
-   Session Manager；
-   重复登录策略；
-   Heartbeat；
-   Idle Timeout；
-   在线状态 Metrics。

### 阶段测试

-   正确 Token；
-   错误/过期 Token；
-   同账号重复登录；
-   心跳正常；
-   心跳停止；
-   网络半开场景模拟；
-   Close 与 Heartbeat 并发。

### 阶段验收

-   未认证连接不能发送业务消息；
-   Session 与 Connection 生命周期一致；
-   僵尸连接在预期时间内被回收；
-   重复登录行为完全符合文档；
-   无明显 goroutine 泄漏。

------------------------------------------------------------------------

## 阶段 3：Backend 路由

### 阶段目标

让 Gateway 真正成为"接入层"，能够把消息交给独立 Fake Backend/Room 服务。

### 任务

-   gRPC 内部接口；
-   MessageType -\> Handler/Backend 路由；
-   User -\> Room；
-   Room -\> BackendInstance；
-   RPC timeout；
-   Backend 错误映射；
-   基础熔断/快速失败策略。

### 阶段测试

-   正常请求；
-   未知 MessageType；
-   Backend 超时；
-   Backend 断开；
-   Backend 返回错误；
-   高并发 RPC；
-   路由表变化。

### 阶段验收

-   Gateway 内不存在游戏规则；
-   替换 Fake Backend 不需要修改客户端协议核心；
-   Backend 故障不会无限阻塞 Gateway；
-   RPC 延迟与错误率可观测。

------------------------------------------------------------------------

## 阶段 4：可靠消息

### 阶段目标

建立可验证的 Seq/ACK/Dedup/Retry
机制，为聊天、关键指令和断线恢复提供基础。

### 任务

-   MessageID；
-   Seq；
-   ACK；
-   Pending Queue；
-   Retry；
-   Dedup Window；
-   超时与最大重试次数；
-   可靠/非可靠消息分类接口。

### 阶段测试

主动注入：

-   丢 ACK；
-   重复包；
-   乱序包；
-   延迟 ACK；
-   连接在 ACK 前断开；
-   重发期间收到 ACK；
-   Seq 边界条件。

### 阶段验收

-   重复消息不会重复产生业务效果；
-   ACK 丢失可触发预期重发；
-   Pending Queue 有严格上限；
-   不存在无限重试；
-   所有可靠性语义均有明确文档。

------------------------------------------------------------------------

## 阶段 5：断线恢复

### 阶段目标

客户端短暂断网后能够恢复原 Session，而不是重新创建完整游戏上下文。

### 任务

-   Resume Token；
-   Session Grace Period；
-   LastAckSeq；
-   Pending Message 恢复；
-   Room 路由恢复；
-   Session 过期回收。

### 阶段测试

-   WiFi/5G 切换模拟；
-   断线后立即恢复；
-   Grace Period 内恢复；
-   Grace Period 后恢复；
-   旧连接与新连接同时出现；
-   Resume Token 重放；
-   恢复期间 Backend 不可用。

### 阶段验收

-   同一 Session 最终只有一个有效连接；
-   恢复后消息顺序符合协议定义；
-   过期 Session 能自动释放；
-   Resume Token 不能无限复用。

------------------------------------------------------------------------

## 阶段 6：多节点 Gateway

### 阶段目标

从单机扩展到多个 Gateway 实例，并只共享真正需要共享的状态。

### 任务

-   GatewayID；
-   Redis 路由状态；
-   User -\> Gateway；
-   TTL/Lease；
-   节点失联后的状态清理；
-   跨节点重复登录处理。

### 阶段测试

-   Gateway A/B 同时运行；
-   用户分布到不同节点；
-   A 崩溃；
-   Redis 短暂不可用；
-   TTL 过期；
-   同账号连接不同 Gateway；
-   节点恢复。

### 阶段验收

-   单 Gateway 故障不污染长期路由；
-   Redis 故障不会立即导致所有已有连接死亡；
-   路由最终可恢复；
-   多节点场景下重复登录策略一致。

------------------------------------------------------------------------

## 阶段 7：背压、限流与优雅下线

### 阶段目标

保证系统在慢客户端、突发流量和发布重启时行为可控。

### 任务

-   Per-Connection Queue Limit；
-   Rate Limit；
-   Message Drop/Coalesce Policy；
-   Backend Backpressure；
-   SIGTERM；
-   Stop Accept；
-   Drain；
-   Graceful Close。

### 阶段测试

-   单客户端洪泛；
-   全局突发流量；
-   慢客户端；
-   Backend 处理速度骤降；
-   压测期间发送 SIGTERM；
-   Drain 超时。

### 阶段验收

-   内存不会因队列无限增长；
-   慢客户端不会拖垮其他连接；
-   Shutdown 过程有 Metrics；
-   发布过程中已接收请求按设计完成或明确失败。

------------------------------------------------------------------------

## 阶段 8：独立项目最终验收

### 阶段目标

证明 Gateway 已经可以作为独立基础设施交付，并为 State Sync
集成做好契约。

### 最终测试

-   长时间稳定性测试；
-   峰值连接测试；
-   峰值消息吞吐测试；
-   Backend 故障注入；
-   Redis 故障注入；
-   Gateway Crash；
-   Graceful Shutdown；
-   Reconnect Storm；
-   race detector；
-   goroutine/heap profile。

### 最终验收物

-   架构说明；
-   协议说明；
-   状态机说明；
-   压测报告；
-   故障测试报告；
-   Metrics 清单；
-   Gateway \<-\> State Sync 接口契约草案。

验收完成后，Gateway 项目冻结第一版接口，进入与 State Sync Server
的集成阶段。
